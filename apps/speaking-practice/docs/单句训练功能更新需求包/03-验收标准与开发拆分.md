# 03 验收标准与开发拆分

## 1. 验收环境

- Windows 11。
- 最新版 Chrome 和 Edge。
- 桌面宽度至少覆盖 1366px。
- 移动端模拟宽度覆盖 390px。
- 使用现有 `public/data/library.json` 和训练视频。
- 使用真实麦克风完成录音验证。

## 2. 核心验收用例

### AC-01 模式切换

操作：打开训练室，切换到单句训练，再切回整段训练。

通过条件：

- 两种模式均可进入。
- 切换时案例暂停。
- 整段训练原有录制和对比流程仍可使用。

### AC-02 选择当前句

操作：在单句模式点击右侧第 3 句。

通过条件：

- 第 3 句成为高亮句。
- 视频停在第 3 句开始时间。
- 页面显示“第 03 / 总句数 句”。

### AC-03 只播放一句

操作：点击“听示范并开始”。

通过条件：

- 视频从当前句开始时间播放。
- 到当前句结束时间后暂停，误差不超过 100 毫秒。
- 下一句内容没有被播放。
- 案例播放时录音状态保持关闭。

### AC-04 自动开始录音

操作：允许麦克风后完成一次案例播放。

通过条件：

- 案例结束后 700 毫秒内进入录音。
- 录音区出现红色状态和计时。
- 按钮文案变为“我说完了”。
- 案例视频保持暂停。

### AC-05 手动结束录音

操作：说完一句后点击“我说完了”。

通过条件：

- 录音立即停止。
- 页面进入可以对比状态。
- 案例和用户录音都可以单独播放。

### AC-06 A→B 连续播放

操作：点击“A→B 连续播放”。

通过条件：

- 先播放案例当前句。
- 案例结束后约 300 毫秒播放用户录音。
- 页面明确显示当前播放的是 A 或 B。
- 两段声音不会重叠。

### AC-07 时长差异

操作：完成一次有效录音。

通过条件：

- 显示案例时长和用户录音时长。
- 显示“快 N 秒”“慢 N 秒”或“时长接近”。
- 数值与媒体实际时长误差不超过 0.1 秒。

### AC-08 重新录制

操作：完成录音后点击“重新录制”。

通过条件：

- 当前句保持不变。
- 上一次用户录音不可再播放。
- 可以重新执行案例到录音流程。

### AC-09 下一句

操作：完成录音后点击“下一句”。

通过条件：

- 下一句成为当前句。
- 视频停在下一句开始位置。
- 旧录音被释放。
- 页面等待用户主动开始，不自动播放。

### AC-10 权限拒绝

操作：拒绝麦克风权限。

通过条件：

- 页面给出明确的重新授权方法。
- 用户仍可以听案例和切换句子。
- 页面没有持续弹出授权请求。

### AC-11 过短录音

操作：开始录音后在 0.5 秒内结束。

通过条件：

- 页面不进入正常对比状态。
- 显示“没有录到完整内容”。
- 提供“重新录制”按钮。

### AC-12 快捷键

操作：使用空格、左右方向键和 `R` 完成训练操作。

通过条件：

- 快捷键行为与页面按钮一致。
- 输入框或权限弹窗获得焦点时不会误触发。

### AC-13 移动端

操作：在 390px 宽度下完成选择句子、听案例、录音和 A/B 对比。

通过条件：

- 无横向页面溢出。
- 主按钮无需放大页面即可点击。
- 当前句和录音状态可见。

### AC-14 资源释放

操作：录音后切换句子、片段和模式，再关闭页面。

通过条件：

- 摄像头和麦克风轨道按规则停止。
- 旧的 Blob URL 被释放。
- 浏览器控制台没有持续增加的媒体相关错误。

## 4. 建议开发拆分

### 任务 1：模式与状态模型

目标：建立整段/单句模式和单句训练状态机。

建议状态：

```text
idle
preparing_permission
playing_example
transitioning
recording_user
processing_recording
ready_to_compare
playing_a
playing_b
error
```

完成条件：状态转换测试通过，录音中无法切换作者、片段和模式。

### 任务 2：句子级案例播放

目标：精确播放当前 cue，并在句尾暂停。

完成条件：随机抽查至少 10 句，结束误差均不超过 100 毫秒。

### 任务 3：单句录音

目标：案例停止后自动录音，支持手动结束、超时结束和资源释放。

完成条件：连续训练 20 句没有录音串音、重复回调或媒体轨道泄漏。

### 任务 4：A/B 对比播放器

目标：支持单独播放和 A→B 连续播放。

完成条件：两段音频不会重叠，暂停、重播和切句行为稳定。

### 任务 5：界面与响应式

目标：增加模式开关、接力条、当前句控制和内嵌对比区。

完成条件：桌面端和 390px 移动端完成核心流程，无明显布局跳动。

### 任务 6：快捷键与无障碍

目标：补齐键盘操作、焦点状态、状态文本和减少动态效果支持。

完成条件：只使用键盘可以完成一轮单句训练。

### 任务 7：回归和真实设备验收

目标：构建、数据、浏览器和真实麦克风联合验证。

完成条件：本文件第 2、3 节全部通过并记录结果。

## 5. 实现建议

- 将整段训练和单句训练的录音状态分开管理，避免一个布尔值承担多个阶段。
- 将媒体操作整理成小函数：播放句子、开始录音、停止录音、播放 A/B、释放资源。
- 句尾控制以 `timeupdate` 配合精确时间检查实现，并在切句、切片段时取消旧监听。
- 录音开始前提前获取麦克风流，确保案例结束后可以快速接棒。
- 第一版继续使用浏览器 `MediaRecorder`，无需新增后端服务。
- 时长差异直接读取案例 cue 时长和录音媒体时长。
